# 0.10.0 功能、安全与性能验收

验收日期：2026-10-04。主控与前端 0.10.0，Agent 0.2.2。新增独立 Nginx + Rust 发行版 rust-v0.10.0，原 PHP 发行版 v0.10.0 保留。

## 发行版与部署

Nginx + Rust 版的页面、静态文件、安装向导、API 与 WSS 均嵌入一个主控二进制。Nginx 提供 HTTPS，主控只监听回环地址；运行无需 PHP-FPM、数据库、Node.js 或 Rust 编译环境。systemd 管理一个主控进程。维护工具与被控 tmux 仍按部署文档安装。

同一源代码生成两种发行包，各自检查对应的签名更新渠道。PHP 版仍为 GitHub latest；Rust 版使用 rust-v 前缀且不替换 PHP latest。两版使用相同 Agent、业务协议及私有数据格式。

amd64 主控 12,705,120 字节（约 12.12 MiB），SHA-256：ac7eb5e5d4749e85a95dd0fdeff1316fe1706c7227e28a22dcf52318208c23a8。
arm64 主控 11,082,560 字节。两种主控和 Agent 均完成 musl 静态构建；本轮真机运行验证为 amd64，不把交叉编译视为 ARM 真机测试。

## 功能实测

- Rust 网页向导：私有所有权链接、HttpOnly Cookie、CSRF、创建管理员、站点标题转义、安装完成跳转、锁定再次安装、源码及私有路径拒绝访问。已有配置禁止覆盖。
- 现有 PHP 测试状态完整迁入 Rust 实例，原管理员与节点凭据保留；原域名下节点重新上线，SSH 与文件操作可用。
- 终端、目录浏览/编辑、文件传输建立三条独立 SSH 连接。16 MiB 下载过程中继续浏览和输入命令，下载哈希一致。
- 浏览器传输中断、测试 Agent 重启、单独中断测试 SSH 传输后，恢复到原 PID、环境变量、工作目录及正在运行的命令；输入不会自动重发。
- 恢复只属于原登录会话：另一登录不能接管或关闭；主动断开、关闭标签、退出登录和远端 exit 均结束原 Shell。
- 异常断开后约 290 秒仍保留，约 315 秒确认清理，过期恢复被拒绝。等待清理按五秒粒度执行。
- 持续连接测试实际运行 1,810 秒，执行 175 次采样命令、收到 70 次 WebSocket Ping，原 Shell 保持不变；没有将该结果表述为一小时或长期稳定性验证。
- 浏览器桌面/手机回归 13 项：取消文件选择不关闭终端，新建文件、编辑保存、1 MiB 上传完整性、手机快捷键反馈、重试/取消、主动关闭及标签数量。
- SSH 真实加密协议测试三项：延迟重新协商超过普通保活窗口仍成功；协商卡住触发独立超时；普通保活无响应触发保活超时。
- PHP 与 Rust 两套隔离实例均完成签名更新→回退→更新，认证文件和主密钥不变；注入更新后健康检查失败，均恢复原程序及私有状态。
- 最终 Web 修正验证 GET/HEAD 内容长度一致，HEAD 不发送正文。

主控 54 项单元测试与 3 项 SSH 协议集成测试、Agent 18 项测试、前端 14 项测试通过。Rust 格式及 Clippy、ShellCheck、shell 语法、Python 编译和 PHP 语法检查通过。

## 同条件资源与吞吐比较

[逐轮数据与方法 JSON](performance-0.10.0.json)。

开发机 Debian 13、4 个逻辑 CPU、16 GiB 内存。两版使用同一最终主控二进制；应用合计限 2 核，压测器单独限 1 核。Nginx 均为单 worker，PHP 8.4 为 8 个静态 worker。经验证证书的本机 HTTPS 请求，200 个模拟 Agent 通过 WSS 每秒上报，200 个客户端同时访问公开节点接口。正式应用限流保持开启；每次换干净的隔离状态，不触及生产节点。

持续场景每客户端约每秒请求一次，每轮 45 秒；突发场景为闭环并发，每轮 10 秒。各跑两轮，顺序交替。下表为两轮算术均值，P95 为两轮 P95 的均值。PSS 合计含 Nginx、PHP（若有）及全部主控进程，排除压测器；避免直接相加 RSS 重复计算共享页。

| 指标 | Nginx + PHP + Rust | Nginx + Rust |
| --- | ---: | ---: |
| 持续场景完成请求/秒 | 199.6 | 199.6 |
| 持续场景平均 PSS | 69.12 MiB | 40.35 MiB |
| 持续场景 CPU（单核 100%） | 68.01% | 30.30% |
| 持续场景 P95 | 294.8 ms | 203.7 ms |
| 10 秒突发完成请求/秒 | 777.2 | 1334.4 |
| 10 秒突发 P95 | 294.4 ms | 202.0 ms |
| 请求错误 | 0 | 0 |
| 最终在线 / 最新上报核对 | 200 / 200 | 200 / 200 |

在这组条件下，Rust 版持续场景内存下降约 41.6%，CPU 下降约 55.4%，短时突发吞吐提高约 71.7%。结论是取消 PHP 网关和额外进程后，本项目实测运行成本下降；不是对所有 PHP 框架、其他硬件或长期最大容量的评价。

实际默认看板刷新是五秒；本次一秒刷新与一秒上报负载更密集。10 秒突发不是长期承载保证，也未包含公网高延时、外部 CDN、全部管理员同时传输大文件等情况。初期发现 Nginx 独立 CPU 上限和超过限流窗口影响结果，修正测试条件后重跑；不使用这些无效轮次推导收益。编译、压缩和浏览器测试与最终性能轮次错开执行。

## 安全检查

动态检查覆盖未登录管理访问、Origin/CSRF、Cookie、CSP、安装占用保护、私有文件泄漏、主题 CSS/图片注入、公开数据脱敏、退出撤销、跨登录终端接管与关闭。Agent 管理证明错误被拒绝，正确证明才能准备 tmux，节点配置保持一致。

依赖扫描使用本次更新的官方 RustSec 数据：
- 主控：1 项既有告警 RUSTSEC-2023-0071 / CVE-2023-49092，rsa 0.10.0-rc.18，上游尚无修复版本。
- Agent：0 项依赖漏洞告警。
- 前端 npm audit：0 项漏洞告警。
- 源码 Gitleaks：0 项发现。两个发布包各有 17 项 generic-api-key 提示，全部位于 SHA256SUMS.json；逐项重新计算对应文件 SHA-256 后确认是校验和误报，未发现真实凭据。另核对私有状态排除、签名和各文件哈希。

当前受管私钥只允许 Ed25519，首次部署为密码认证，RSA 特性保留用于已有服务器的 RSA-SHA2 主机公钥验签。根据当前调用路径，没有暴露受影响的 RSA 私钥运算；该判断不能将上游告警消除。详见 [安全边界](RUST-SECURITY.md) 及 [官方公告](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)。

本次修正了测试中发现的 tmux 定时任务过早展开状态、PHP 更新后的启动就绪重试和 HTTP HEAD 长度问题，并完成对应回归。扫描和模拟测试不能保证不存在未知漏洞。

新安装向导、systemd 与 Nginx 代理已实测。一键脚本通过静态检查和当前 Debian 环境检测；没有在一台全新公网主机重新申请 ACME 证书，也没有逐个发行版和 ARM 真机重装。已有 PHP 一键部署继续保留，Rust 手动宝塔部署见 [完整教程](Nginx-Rust部署教程.md)。
