# 终端输出与回滚记录（0.10.1）

本版将独立 Rust 版 v0.10.2 的终端修复同步到 Nginx + PHP 版；PHP 网关、网页安装向导和原仓库更新来源保持兼容。

本版修复 SSH 终端输出超过一屏后无法用滚轮回看的问题。刷新站点并重新连接终端后生效；旧版没有送达浏览器、且已超出远端缓存的输出无法补回。

## 使用方式

- 电脑使用鼠标滚轮或滚动条上翻；手机在终端区域上下滑动。
- 阅读历史时，新输出不会强制拉回底部。输入命令时回到当前终端位置。
- “查找”可搜索缓存中的内容；全屏程序（例如 less）继续使用自己的交互方式，退出后返回原终端记录。
- 每个终端保留最近 5,000 行回滚记录。缓存有上限，适合手机和长时间运行；不提供无限日志归档。
- 异常断线仍在 5 分钟恢复窗口内恢复原 Shell 和远端保留的历史。点击“断开”、关闭标签、退出登录仍会结束该会话。

## 修复方式

此前连接的是 tmux 的屏幕界面：它会进入备用屏幕，而且高频输出可能合并成一次屏幕重绘。这种方式不适合浏览器积累完整输出。

现在通过 [tmux control mode](https://github.com/tmux/tmux/wiki/Control-Mode) 接收原始 PTY 字节，由浏览器终端负责渲染和滚动。连接和恢复时，在同一个 tmux 命令队列内建立订阅、读取屏幕与历史，再继续实时输出。历史转义与实时输出转义分别解码。

小块输出最多合并 8 毫秒，避免大量短行触发过多浏览器确认帧。原有输出流控、输入限额、独立心跳与 SSH 密钥重新协商机制继续生效。SSH 文件浏览与传输仍使用独立连接。

## 安全与资源边界

- 终端授权仍绑定当前管理登录、节点和随机会话标识；跨登录会话不能恢复或关闭别人的终端。
- 键盘与粘贴输入按字节编码为十六进制再送入 tmux，不将输入拼成 tmux 命令或 Shell 参数。
- 控制记录限制为 256 KiB；每份恢复屏幕按 4 MiB 和 5,120 行双重限额保留最近内容。超出协议边界的内容拒绝处理。
- 浏览器仍禁止终端内容修改剪贴板、创建终端链接或改写页面标题。触摸滚动只移动浏览器视图，不向 Shell 注入方向键。
- 不增加持久化的终端日志文件；会话关闭沿用既有清理机制。Nginx 配置和 Agent 0.2.2 无需调整。
- 依赖扫描中的既有 RSA 上游告警与适用边界见 [安全说明](RUST-SECURITY.md)。本版没有新增依赖。

实际验收结果随 Release 的 `verification-0.10.1.json` 提供。ARM64 提供交叉编译产物，不将其等同于 ARM 真机功能验收。
