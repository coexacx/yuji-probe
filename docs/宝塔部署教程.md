# 羽迹探针 0.6.0 GitHub 版：从零开始的宝塔部署教程

适用对象：第一次部署本探针面板的使用者，以及已经安装宝塔、希望增加一个探针网站的管理员。本文按“准备服务器 → 安装宝塔 → 配置网站 → 首次安装 → 接入节点 → 日常维护”的顺序编写。核对日期：2026-09-30。

本包为正式数据模式，安装后服务器列表为空。界面 **0.9.1**，Rust 主控 **0.9.1**，Rust Agent **0.2.1**。Nginx 和 PHP 的安装方法保持不变，通信主控与被控已改用随包 Rust 二进制。普通用户无需现场编译，也不需要数据库。

## 下载正确的安装包

从 [coexacx/yuji-probe 的 v0.9.1 Release](https://github.com/coexacx/yuji-probe/releases/tag/v0.9.1) 下载 **yuji-probe-panel-0.9.1.zip** 和同名 **.zip.sha256** 文件。不要使用 Code → Download ZIP 或 Source code 包：它们没有预编译主控。

本 GitHub 专属版从同一 Release 下载 Rust Agent，不需要访问原来的二进制下载域名。主控必须能通过 HTTPS 访问 **github.com**、**release-assets.githubusercontent.com**；部分历史发布资产可能使用 **objects.githubusercontent.com**。网络不通时部署停止，不跳过签名或关闭证书验证。GitHub 下载发生在主控，由主控通过 SSH 上传到节点。

宝塔手动部署继续保留网页安装向导。**不要在已安装宝塔或已有网站的服务器上运行 Linux 一键脚本**。

## 2. 准备服务器、域名和访问端口

### 2.1 主控环境

本文以 Debian 12、x86_64 的宝塔服务器作为部署示例。主控需要 Linux、Nginx、PHP 和 HTTPS；不需要 MySQL、Redis、Composer、Node.js、Rust 或 Go 编译器。源码包已经包含 amd64 / arm64 通信程序。

PHP 源码最低要求是 8.0，但新部署建议使用本项目实际验收过、仍在官方维护期的 **PHP 8.4**。不要将“能够运行旧版本”理解为建议使用停止维护的版本。版本维护情况可在 [PHP 官方支持列表](https://www.php.net/supported-versions.php) 查询。

容量取决于节点、访问量、SSH 会话数和同机其他程序。首次小规模部署可以先预留约 2 GB 内存和足够的磁盘空间，再按照真实负载观察调整；这属于部署余量建议，并非容量承诺。本包的短时隔离压测条件和结果见 [测试报告](测试报告.md)。

被监控服务器支持多种常见 Linux 发行版与 systemd，架构为 amd64 或 arm64。版本列表见[系统支持](系统支持.md)，实际测试范围见本版验收报告。

### 2.2 解析域名

1. 打开域名的 DNS 管理页。
2. 添加一条 A 记录：主机名 `probe`，记录值为主控公网 IPv4。
3. 若没有可用公网 IPv6，不要添加 AAAA 记录；已有错误 AAAA 记录应先纠正，否则部分访客和 Agent 会走错误地址。
4. 初次部署建议先使用直接 DNS 解析，完成源站 HTTPS 和 WSS 验证后再启用 CDN。
5. 等待解析生效。在本机终端执行：

```sh
nslookup probe.example.com
```

应看到主控服务器的真实 IP。若启用了代理/CDN，查询结果会是代理地址，这时需同时检查 DNS 服务商后台的源站记录。

### 2.3 端口规则

云服务器安全组和服务器本机防火墙是两层控制，两处都需要检查。

| 端口 / 方向 | 用途 | 建议范围 |
| --- | --- | --- |
| 主控入站 TCP 80 | HTTP 跳转、部分证书验证 | 公网 |
| 主控入站 TCP 443 | HTTPS 页面、Agent WSS、浏览器终端 | 公网或您明确允许的访问范围 |
| 主控入站 SSH 端口 | 系统管理 | 管理员来源 IP |
| 主控入站宝塔管理端口 | 宝塔后台 | 管理员来源 IP；以安装输出为准 |
| 被监控服务器 SSH 端口 | 首次远程安装 / 后续重新部署 | 主控出口 IP，以及您自己的管理来源 |
| 被监控服务器出站 TCP 443 | 连接主控、获取签名 Agent | 必须可达 |
| 主控出站 TCP 443 | 获取 Agent、调用 Telegram | 必须可达 |
| `127.0.0.1:19281` | PHP 与通信服务的内部接口 | **仅回环，不开放公网** |

系统还需能通过已有 DNS 解析器解析域名，并访问对应发行版的软件仓库。Agent 不会额外开放公网监听端口。安装成功后终端使用 Agent 通道，日常管理仍应保留一个可恢复系统的独立 SSH / 云控制台入口。

## 3. 在全新服务器上安装宝塔

本节只适用于尚未安装宝塔、且没有运行现有网站的全新系统。若服务器上已经有站点，使用现有环境新增网站。

### 3.1 连接系统 SSH

Windows 可打开系统终端，macOS / Linux 可打开 Terminal。执行下面的示例命令，替换 IP 和实际端口：

```sh
ssh -p 22 root@203.0.113.10
```

首次连接会显示服务器主机指纹，应与云控制台提供的信息或可信管理入口核对。输入密码时终端通常不显示字符，这是正常行为。若使用普通系统管理员账户，按服务器的管理方式使用 `sudo` 获取安装权限。

确认登录的是准备安装的主控机器：

```sh
hostname
cat /etc/os-release
uname -m
```

### 3.2 获取宝塔官方安装命令

打开 [宝塔官方下载页](https://www.bt.cn/new/download.html)，选择适合当前系统的 Linux 稳定版本，复制页面当时提供的安装命令，在系统 SSH 中执行。官方命令会更新，后续部署时优先使用该页面的当前版本。

截至本文核对日期，官方稳定版脚本为 `installStable_12.sh`。下面分两步下载和运行，便于确认下载成功后再执行：

```sh
curl -fL --proto '=https' --tlsv1.2 https://download.bt.cn/install/installStable_12.sh -o /root/installStable_12.sh
bash /root/installStable_12.sh 5x59vxy56
```

若系统没有 `curl`，可以使用官方下载页提供的 `wget` 版本，或先通过系统软件包管理器安装 `curl`。安装过程中的系统路径、确认提示以官方安装器为准。

安装结束后，保存输出的宝塔地址、实际管理端口、安全入口路径、用户名和密码。不要把这些信息截图公开。然后在安全组中只对自己的管理来源放行宝塔端口。

忘记安装输出时，可在系统 SSH 中查看：

```sh
bt default
cat /www/server/panel/data/port.pl
```

这些命令会显示敏感管理信息，仅在您自己的终端使用。上述查询方式来自 [宝塔官方安装说明](https://www.bt.cn/new/download.html)。

### 3.3 首次登录宝塔

使用安装器给出的完整地址，包括端口和安全入口。若管理端口使用服务器自签名证书，先通过可信的服务器控制台核实目标，再为宝塔管理入口配置您信任的 HTTPS 证书。不要把探针站点域名与宝塔管理入口混用。

登录后修改宝塔初始密码，设置安全入口，并限制可访问后台的 IP。若出现环境推荐安装弹窗，按下一节选择所需软件即可。

## 4. 安装 Nginx 和 PHP

1. 在宝塔进入“软件商店”。
2. 安装 Nginx；已有 Nginx 的机器直接使用现有服务。
3. 安装 PHP 8.4，已有符合要求的 PHP 也可以使用。
4. 打开 PHP 设置，检查 cURL、OpenSSL、Session 扩展已启用。
5. 本程序不用数据库，不必为了本程序安装 MySQL，也不需要创建数据库。

不要在现有站点使用 Apache 的生产服务器上直接切换全局 Web 服务。需要 Nginx 时，应先规划服务迁移或使用独立服务器。

**本步完成标志：**宝塔软件列表中 Nginx 与选用的 PHP 正常运行。

## 5. 创建网站、上传源码、设置运行目录

### 5.1 创建网站

在宝塔“网站 → 添加站点”填写：

- 域名：`probe.example.com`，不要填 `https://`。
- 根目录：`/www/wwwroot/probe`。
- PHP 版本：选择刚安装的版本。
- FTP：不创建，除非您有其他用途。
- 数据库：不创建。

### 5.2 上传并解压

1. 从可信发布位置取得源码 zip 和对应 `.sha256` 文件。
2. 在宝塔文件管理器打开 `/www/wwwroot/probe`。
3. 上传 zip，点击解压。
4. 压缩包包含最外层 `yuji-probe-panel-0.9.1/` 文件夹。将它**里面的内容**移到项目目录，确保结构如下：

```text
/www/wwwroot/probe/
├── app/
├── bin/
│   ├── probe-linux-amd64
│   └── probe-linux-arm64
├── docs/
├── ops/
├── public/
│   ├── index.php
│   └── assets/
├── source/
├── storage/
├── README.md
└── SHA256SUMS.json
```

如果不移动外层目录，也可以保留它，但后续所有项目路径必须一起加上这一层，不能混用两种路径。

使用系统 SSH 校验下载包时，在 zip 和 `.sha256` 所在目录执行：

```sh
sha256sum -c yuji-probe-panel-0.9.1.zip.sha256
```

应显示 `OK`。校验和用于发现传输或文件损坏；若压缩包和校验文件都来自不可信来源，仅比对它们不能证明发布者身份。

### 5.3 设置运行目录

进入“网站 → 当前站点 → 网站目录”：

- 网站目录保持 `/www/wwwroot/probe`。
- **运行目录选择 `/public`。**
- 默认文档包含 `index.php`。

最后生效的 Nginx `root` 必须为：

```nginx
root /www/wwwroot/probe/public;
index index.php;
```

不能把项目根目录直接公开，否则私有文件可能被错误暴露。上传的压缩包也不要留在 `public/` 中。旧的默认欢迎页若位于 `public/`，请确认来源后移走，避免优先显示它。

## 6. 配置目录权限和 PHP

### 6.1 文件权限

先确认网站 PHP-FPM 的实际运行用户。普通宝塔环境常见为 `www`；如果您使用独立站点用户，应改成该用户。不要仅根据 Nginx 用户猜测 PHP 用户。

以下命令**只针对示例项目**，先核对目录后再执行：

```sh
chown -R www:www /www/wwwroot/probe/storage
chmod 700 /www/wwwroot/probe/storage
chmod 755 /www/wwwroot/probe/bin/probe-linux-amd64
chmod 755 /www/wwwroot/probe/bin/probe-linux-arm64
```

普通代码目录可为 755、文件可为 644，建议由部署管理员持有，PHP 只读。安装器会在 `storage/` 中创建权限为 600 的私密文件及权限为 700 的子目录。新安装的 `storage/` 应为空，除 `.gitkeep` 外不包含旧站运行数据。

不要将目录设为 777，也不要在已有站点上对整个项目递归改成全员可写。`storage/` 中的主密钥和配置需由同一个受信任的 PHP / 通信服务账户读取。

### 6.2 允许后台进程函数

打开选用 PHP 版本的设置，查找“禁用函数”。确保 `proc_open` 和 `proc_close` 不在禁用列表中。安装器使用它们启动随包的通信程序；不用额外开放 `system`、`exec` 等函数。

保存后按宝塔提示重载 PHP。若该 PHP 版本同时服务其他网站，这属于共享配置变化；多站点环境优先为探针单独配置 PHP-FPM 池和运行账户。不要通过随意解除所有禁用函数解决问题。

### 6.3 调整防跨站路径限制

宝塔的 `open_basedir` 若只允许 `/public`，PHP 就无法读取上层 `app/`、`bin/`、`storage/`。需要允许**整个项目目录**。

在宝塔当前网站的“防跨站攻击 / open_basedir”设置中调整范围。若界面只能开关，可以关闭当前站点自动生成的限制，再由管理员为该站点的 `.user.ini` 或独立 PHP-FPM 池写入正确范围。示例 `.user.ini` 放在 `/www/wwwroot/probe/public/.user.ini`：

```ini
open_basedir=/www/wwwroot/probe/:/tmp/:/etc/ssl/certs/
```

保留系统实际使用的 CA 证书路径；若您的 PHP CA 配置在其他路径，应按实际情况加入。不要把限制直接扩展为系统根目录。宝塔可能给 `.user.ini` 添加不可修改属性，优先通过网站设置解除后编辑，避免对未知文件批量执行属性修改。

`.user.ini` 的读取有缓存，保存后可重载该 PHP 服务以使其及时生效。本站 Nginx 会阻止网页访问点开头的文件。

**本步完成标志：**首次安装页面的 PHP、扩展、目录、后台进程检查均显示“就绪”。若还没有 HTTPS，请先完成下一节再访问安装器。

## 7. 申请 HTTPS 证书

1. 进入“网站 → 当前站点 → SSL”。
2. 选择证书申请功能，勾选 `probe.example.com`。
3. 根据域名情况使用文件验证或 DNS 验证。文件验证需要域名指向正确主机，且验证路径可以经 TCP 80 访问。
4. 申请并部署证书后，确认浏览器访问 `https://probe.example.com` 无证书错误。
5. 启用自动续期，并按宝塔功能启用 HTTP 到 HTTPS 跳转。

证书必须覆盖您实际使用的域名。不要在域名证书下改用 `https://IP` 安装；安装器会锁定当时的域名，Agent 也需要验证 WSS 的 TLS 证书。

若使用 CDN，源站也要有有效证书，并使用严格验证源站证书的 HTTPS 模式。不要使用只在浏览器到 CDN 之间加密、CDN 到源站走 HTTP 的模式。

证书验证的 `/.well-known/` 配置通常由宝塔提供。后面加入的私有文件规则不能替换宝塔现有证书验证配置；若申请或续期失败，检查 Nginx location 优先级和实际验证路径。

## 8. 配置 Nginx 路由与 WSS

恢复加密备份需要在本站 HTTPS server 块设置一次 client_max_body_size 24m;，PHP 设置 post_max_size=24M、memory_limit=128M 或以上。其他 JSON 管理请求仍由服务端限制为 16 KiB。

### 8.1 为什么必须配置两个 WSS 路由

页面和普通 API 由 PHP 处理；持续连接由随包的通信程序处理。`/api/agent` 是节点通道，`/api/terminal` 是浏览器终端通道，两者必须经过 Nginx WebSocket 代理。

PHP 网页能打开而服务器始终离线，经常是这一步遗漏。

### 8.2 填写本站“伪静态”

打开“网站 → 当前站点 → 伪静态”。复制源码包 `ops/baota-rewrite.conf` 的完整内容并保存。0.4.0 的内容如下；如果后续版本更新，以对应压缩包内文件为准：

```nginx
location ~ ^/(?:app|bin|storage|backend|src|source|docs|ops|qa|vendor|node_modules)(?:/|$) { return 404; }
location ~ /\. { return 404; }

location = /api/agent {
    proxy_pass http://127.0.0.1:19281;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 65s;
    proxy_send_timeout 15s;
    proxy_buffering off;
    proxy_intercept_errors on;
    error_page 502 = /index.php?probe_wake=1;
}

location = /api/terminal {
    proxy_pass http://127.0.0.1:19281;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 65s;
    proxy_send_timeout 15s;
    proxy_buffering off;
    proxy_intercept_errors on;
    error_page 502 = /index.php?probe_wake=1;
}

location / {
    try_files $uri /index.php$is_args$args;
}
```

不要重复添加 `location /`。若当前站点原来有 WordPress、其他程序的伪静态或整站反向代理，应先保存其备份，再仅修改这个新建探针站点的对应规则。不要修改其他域名的配置。

### 8.3 检查站点配置文件

在本站的“配置文件”中核对 HTTPS 对应的 `server` 块：

```nginx
server_name probe.example.com;
root /www/wwwroot/probe/public;
index index.php;
client_max_body_size 16k;
client_header_timeout 10s;
client_body_timeout 10s;
send_timeout 15s;
keepalive_timeout 30s;
autoindex off;
```

这些是需要核对的指令，**不是完整配置文件**。保留宝塔生成的监听端口、证书路径、SSL 设置、PHP 引用、伪静态引用和证书验证段落。已有同名指令应修改原值，不要再重复粘贴。

如果 `server_name` 有多个名称，请将正式安装域名写在第一位，不要使用 `_` 作为本程序安装域名。程序的首次所有权链接从 Nginx 可信配置中获取站点名称。

PHP 版本为 8.4 时，宝塔通常会引用对应的 PHP 配置，例如 `enable-php-84.conf`；实际以宝塔生成内容为准。不需要手写一个指向其他 PHP 版本的重复 PHP location。

验证 Nginx 配置：

```sh
/www/server/nginx/sbin/nginx -t
```

出现语法正确提示后，通过宝塔重载 Nginx。若校验失败，不要继续重载，先按错误中给出的文件和行号处理；重复 location、重复指令、错误证书路径都应先解决。

### 8.4 CDN 和真实来源 IP

第一次部署可保持直连，减少排错因素。启用 CDN 后，要确认其支持 WebSocket，且 `/api/agent` 的连接不会被要求完成浏览器 JavaScript 验证。Agent 使用节点密钥鉴权，无法通过人机验证页面。

如使用 Cloudflare，可参考包内 `ops/cloudflare-realip.conf`，并与 [Cloudflare 官方 IP 列表](https://www.cloudflare.com/ips/) 核对后更新。只信任实际代理地址；不能把 `set_real_ip_from` 配成任意公网来源，否则攻击者可以伪造 IP 绕过按来源限流。

### 8.5 一台主机部署多份本面板

每份安装需要独立的项目目录、`storage/`、PHP-FPM 池和内部端口。默认 `127.0.0.1:19281` 只供一份面板使用。第二份需要在它的 PHP-FPM 池设置 `PROBE_LISTEN` 为另一个回环端口，并同步修改其两个 WSS `proxy_pass`。

不要让两份站点共用 storage，也不要为解决冲突把内部监听改成公网地址。没有多实例需求时保留默认值即可。

## 9. 完成网页安装向导

### 9.1 取得服务器所有权链接

访问 `https://probe.example.com`。新站首次显示“准备安装”，提示读取 `storage/setup-link.txt`。

1. 回到宝塔文件管理器。
2. 打开 `/www/wwwroot/probe/storage/setup-link.txt`。
3. 复制里面的完整 HTTPS 链接到浏览器。
4. 该链接确认服务器所有权后，页面显示“设置你的探针看板”。

链接不能通过公开网址直接下载，这是预期保护。不要把完整链接转发到聊天群或放进教程截图。文件在第一次访问后才生成，上传源码后尚未打开网站时可能还不存在。

### 9.2 填写三个字段

| 字段 | 填写要求 |
| --- | --- |
| 站点名称 | 您希望访客看到的名称，界面最多 60 字符；例如“我的服务器” |
| 管理员用户名 | 字母或下划线开头，之后可用字母、数字、下划线、点、短横线；最多 32 字符 |
| 管理员密码 | 12 至 72 字节；建议使用密码管理器生成，并独立保存 |

检查环境项目均为“就绪”，点击“完成安装”。程序会自动生成配置、随机主密钥、密码哈希，并启动随包通信服务。

成功后跳转回看板并打开登录弹窗。输入刚设置的管理员账户登录。

**正常结果：**没有演示服务器，管理员可以看到后台菜单；安装链接已删除，重复安装入口已锁定。页头、浏览器标题与登录弹窗中的站点名称都来自您设置的名称。

安装失败后不要反复删除 `storage/`。如果已经生成部分安装数据，先检查错误和日志，再用上次填写的同一组管理员信息重试；避免不必要地丢失密钥和已有状态。

## 10. 接入第一台监控服务器

### 10.1 在节点上准备条件

- 系统在[支持列表](系统支持.md)内，使用 systemd。
- 主控能连接该节点的实际 SSH 端口。
- 您有可进行自动安装的 SSH 账户：root，或拥有 sudo 权限的管理员；普通账户使用填写的密码完成 sudo 验证。
- 当前界面使用用户名和密码完成首次部署，请使用已配置好相应认证方式的账户。不要为了方便而对整个公网放宽 SSH 策略。
- 节点可以访问当前主控 HTTPS 域名；GitHub 发布资产由主控下载并校验后经 SSH 上传。
- 节点时间正确，TLS 证书验证正常。

节点无需安装宝塔、PHP、数据库、Rust、Go 或 Node.js。主控会检查系统并安装所需工具、下发配置和预编译 Agent。

### 10.2 在探针后台添加节点

1. 点击看板右上角小设置图标，登录管理员。
2. 进入“服务器 → 添加服务器”。
3. 填写服务器名称、SSH IP、端口、用户名和密码。
4. 国家保持自动识别；城市可选填。需要手动指定时，可在界面选择国家。
5. 选择是否公开展示。未勾选的节点只对管理员可见。
6. 点击“安装并接入”。

首次检查 SSH 主机时会显示指纹。通过可信服务器终端核对，例如：

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

如果程序实际协商的是其他类型主机密钥，应核对对应的 `.pub` 文件。确认匹配后点击信任并继续，不能仅因出现弹窗就无条件接受。

### 10.3 等待部署与首个监控上报

后台会显示部署进度。首次安装可能受软件仓库和下载链路影响，需要等待。完成后，Agent 通过 WSS 连接当前面板，卡片出现真实 CPU、内存、磁盘、系统和国家信息。

国家通过节点网络信息自动识别，支持 250 个国家与地区及本地旗帜资源；若识别不可用或不准确，可在节点编辑中修正。未启用 Swap 时隐藏整个 Swap 区域，启用后才显示占用。

检查以下结果：

- 状态从“待接入”变成“在线”。
- 管理员列表可以看到 Agent 版本。
- 服务器卡片显示通讯延时；详情中已移除通讯延时角标。
- 数值随刷新更新。该延时是 Agent 与主控 WSS 应用层往返延时，不是访客浏览器到节点的 Ping。
- Agent 离线或尚无有效样本时显示“通讯 —”，不会继续展示旧值。

主控机器不会自动成为监控节点；想监控主控本身时，需另外按节点方式添加。

节点侧排错命令：

```sh
systemctl status vistart-probe-agent --no-pager
journalctl -u vistart-probe-agent -n 80 --no-pager
```

Agent 文件通常位于 `/opt/vistart-probe-agent/agent`，私有配置位于 `/var/lib/vistart-probe-agent/config.json`。配置中包含节点密钥，不要发送其全文或公开日志中的敏感内容。

在线移除会停止本 Agent、清除连接配置和面板专用 SSH 密钥，再删除记录。离线移除立即删除本地记录并撤销凭据，不排队、不补发远程清理。服务器其他应用不作修改。

## 11. 看板、终端和常用命令

### 11.1 访客与管理员看到的内容

公开看板展示节点名称、国家、CPU、内存、已启用的 Swap、磁盘和网卡监控。IP、供应商、供应商站点、到期时间、SSH 用户名和管理操作只提供给已认证管理员。卡片提供通讯延时，详情不再重复显示角标。

管理员登录后可返回看板，在卡片看到 IP 和 SSH 入口；点击详情，查看完整监控指标。修改站点名称后，页头、登录弹窗、页脚和浏览器标题同步更新，重新打开页面也使用新名称。

### 11.2 浏览器 SSH

1. 确认 Agent 在线。
2. 在卡片或后台节点列表点击“SSH”。
3. 在终端窗口点击连接，等待 SSH 会话建立。
4. 首次验证可执行只读命令，例如 `uname -a`、`uptime`。
5. 使用完成后关闭终端或退出管理员。

终端命令以部署时授权的 SSH 账户权限执行；如果该账户是 root，命令就具有 root 权限。Agent 通道不能替代对管理员账户、主机指纹和命令来源的管理。

### 11.3 手机粘贴

在终端窗口点击“粘贴命令”，在弹出的文本框长按粘贴，检查内容后点击“发送并执行”。支持多行，最多 8192 字节。中文字符占用多个 UTF-8 字节，因此可输入的中文字符数量少于 8192 个。

多行文本可能包含多条立即执行的命令，发送前逐行检查。取消、关闭弹窗、断线或退出登录都会清空尚未发送的内容。

### 11.4 常用命令

进入“常用命令 → 添加命令”，填写名称和脚本并保存。连接终端后可选择对应命令并执行，也可编辑或删除它。

建议先保存一个只读命令，例如：

```sh
uname -a
uptime
```

常用命令不是定时任务；保存不会自动执行。只保存您理解且信任的脚本。

### 11.5 左侧文件管理与在线编辑

SSH 连接成功后，左侧显示可折叠的目录与文件列表。点击目录展开或通过路径栏直接跳转；工具栏可返回根目录、家目录、上一级并刷新。列表按页读取，大目录可继续加载。

点击普通文本文件可在侧栏编辑，修改后点击保存。保存会检查是否被其他会话或程序修改，发生冲突时保留当前编辑并要求重新读取合并。默认**不备份原文件**；重要配置修改前请自行确认内容。写入会尽力完整保留权限、属主和扩展属性，无法保留时拒绝替换。

在线编辑限制为 256 KiB UTF-8 普通文本。二进制文件、运行目录、硬链接或不支持安全替换的远端只允许查看或拒绝操作，避免改变原有链接与文件语义。访问范围完全受 SSH 登录用户权限控制；root 连接具有 root 权限。

### 11.6 网卡速度与累计流量

卡片和详情可选择网卡，显示该网卡当前收发速度与累计上传、下载字节数。速率由相邻采样差值计算；网卡累计值来自 Linux 计数器，通常随重启、网卡重建或计数器重置清零。它不是运营商月账单，也不表示面板开始运行后的累计流量。

### 11.7 供应商、到期日与续费提醒

添加或编辑服务器时，可以填写供应商名称、供应商网址和到期时间，并选择是否通知续费。供应商网址仅允许 http/https，相关信息只对管理员展示。

提醒按 UTC+8 的自然日期计算，提前 3 天开始；同一天到期的服务器聚合展示。管理员登录后可选择：

- “稍后提醒”：关闭本次访问弹窗，下次访问还会出现。
- “已续费”：到期时间按节点设置的周期顺延，也可填写实际续费后的到期时间；旧到期周期的弹窗和待发送 Telegram 提醒失效；进入下一周期后再次提醒。
- “不再续费该服务器”：保留到期日并关闭该服务器续费提醒，需要时可在节点编辑中重新开启。

若服务器已逾期很久，顺延一个周期后仍可能处于到期提醒范围，请按供应商实际账单填写新到期日期。面板不会自动向供应商付款。

## 12. 站点名称、二步验证与 Telegram

### 12.1 面板设置

- **站点名称：**保存后所有站点标识同步更新。
- **刷新间隔：**允许 3～30 秒，这是页面轮询间隔。
- **允许访客查看服务器看板：**关闭后匿名访客看不到节点数据，管理员仍能登录管理。

页面轮询间隔、Agent 上报周期和通知防抖时间是不同参数，不能用提高网页刷新频率解决 Agent 无法连接的问题。

### 12.2 开启身份验证器

1. 进入“面板设置 → 二步验证”。
2. 输入当前管理员密码，点击“开始绑定”。
3. 页面同时显示二维码和手动密钥。
4. 使用支持 TOTP 的验证器扫码，或手动录入密钥。
5. 将恢复所需密钥安全保存在密码管理器，避免截图公开。
6. 输入验证器当前的 6 位动态码，点击“验证并启用”。

二维码在当前浏览器本地生成，不通过外部二维码网站生成。开启后登录需要密码和动态码。关闭时也要输入当前密码和新的动态码；刚刚使用过的验证码不能重复使用，必要时等待下一组。

若验证码一直不正确，先检查手机和主控时间同步，不要通过关闭安全校验解决。Linux 可先查看：

```sh
timedatectl status
```

验证器遗失时，在登录验证码栏填写一条未使用的恢复码，并输入正常密码。登录后，可用另一条未使用的恢复码配合密码关闭二步验证。恢复码也遗失时，按[运维与恢复](运维与恢复.md)使用仅限 root 的专用重置命令。

### 12.3 配置 Telegram 通知

1. 在 Telegram 按 [官方 BotFather 说明](https://core.telegram.org/bots/features#botfather) 创建您自己的 Bot，并取得 Token。
2. 用户私聊接收时，先打开这个 Bot 并发送 `/start`，否则 Bot 通常无法主动开始私聊。
3. 准备自己的接收人 Chat ID；群组可能使用负数 ID，应使用实际群组 ID，并确保 Bot 已加入且有发言权限。
4. 进入探针后台“Telegram 通知”。
5. 填入 Bot Token、接收人 ID，开启通知，并按需勾选上线、离线和续费提醒。
6. 点击“保存设置”，再点击“发送测试通知”。

测试按钮每 60 秒最多提交一次。界面会显示待发送、发送成功或失败提示。Token 加密保存在私有目录；保存后输入框不回显，后续留空表示保留，勾选清除才会删除。

离线通知有防抖，短暂抖动不会立即推送；主控重启后也有恢复宽限。发送失败会在有界队列中重试，不依赖您持续打开浏览器。网络中断、第三方限制或队列达到上限仍可能影响送达，请结合通知状态和操作记录排查。

主控服务器本身停机或无法访问 Telegram 时，主控不能替自己及时发出通知；需要另外的外部可用性监测来覆盖这一情况。

## 14. 备份、升级和迁移

### 14.1 应当备份什么

最重要的是完整 `storage/`。其中包括：

- `installed.json`：安装域名及内部监听配置。
- `control/app.key`：加密主密钥。
- `control/auth.json`：管理员密码哈希、验证器状态。
- `control/nodes.json`：节点、站点设置、常用命令和加密身份信息。
- `control/ssh-pins.json`：受信任的 SSH 主机身份。
- `control/telegram.json`：通知设置和状态。
- 其他由程序维护的私有状态文件。

密钥和配置必须配套恢复。丢失 `app.key` 后，单独保留密文配置不足以恢复原有密钥。不要把真实 storage 放入公开源码包或公开下载目录。

同时保存当前源码版本、本站 Nginx / PHP 配置及 HTTPS 证书恢复方式。源码压缩包是安装包，不是生产数据备份。

### 14.2 创建私密备份

在系统管理员终端中执行，先替换真实项目路径。备份位置选网站目录之外，例如 `/root/probe-backups`：

```sh
install -d -m 700 /root/probe-backups
umask 077
tar -czf /root/probe-backups/probe-storage-$(date +%Y%m%d-%H%M%S).tar.gz -C /www/wwwroot/probe storage
```

运行中打包只能得到文件级备份；重要迁移需要一致性备份，应安排维护窗口暂停本面板的写操作，并采用文件系统快照或停止**本实例**通信进程后备份。不要为了备份该面板停止整机其他网站。

建议再保存一份加密的异地备份，并定期在隔离环境演练恢复。不要将备份路径改为 `public/`、下载站或其他对访客开放的位置。

### 14.3 更新源码

1. 阅读新版本说明、组件版本和测试报告。
2. 备份当前代码、完整私有状态、本站 Nginx / PHP 配置。
3. 将新 zip 解压到独立临时目录，先核验校验和。
4. 对照目录，只更新程序代码和构建资源；**保留现有 storage，不把新包中的空目录覆盖成新安装。**
5. 先发布新 `public/assets/`，再替换 PHP 与页面模板，避免新 HTML 引用尚不存在的资源。
6. 若新版本更换了通信二进制，再按该版本说明原子替换文件并重启本实例通信服务；不要直接覆盖仍在运行的可执行文件。
7. 若开启了 PHP OPcache，应按其配置等待文件重新验证，或重载本站的独立 PHP 池。
8. 验证管理员、节点、站名、二步验证、通知设置和在线状态保留。
9. 确认稳定后再清理旧构建文件和临时包，保留可回滚备份。

本次 **Go → Rust** 需要替换主控二进制并重启本实例。完整保留旧 storage，现有密码、二步验证、站点、主机指纹和节点密钥继续使用。主控切换后先确认旧 Agent 恢复上报，再逐台更新 Agent。重启会结束当前浏览器终端，需要重新连接。全局重启 PHP/Nginx 可能影响其他网站，应仅操作本站服务。

### 14.4 更换服务器或域名

**只更换主控服务器、保留域名：**先在新主机准备相同运行环境和有效 HTTPS，恢复配套私有状态与权限，停止旧实例接受节点，再切换 DNS 并确认节点重连。不要让两台主控长期同时使用同一份节点身份运行。

**更换域名：**在新域名完成安装，导入旧主控加密备份。新站保留当前域名，恢复备份中的账户及数据；域名变化时主动通过专用 SSH 恢复密钥改写 Agent 连接并轮换凭据。旧主控可以离线，但节点须已安装 0.2.0 恢复通道且 SSH 对新主控可达。详见[运维与恢复](运维与恢复.md)。

如果您不熟悉私有配置迁移，请先在隔离环境演练并验证备份，而不是在唯一生产副本上反复尝试。

## 15. 故障排查

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 打开域名是另一个站点 | DNS / AAAA、HTTPS `server_name`、是否误改了别的 vhost | 修正本站绑定和解析，保留其他站点配置 |
| 403 / 显示目录页 | 运行目录、默认文档、目录权限 | root 指到实际 `public`，index 包含 `index.php` |
| 页面返回 404 | 外层目录是否多一层、伪静态是否加载 | 核对 `public/index.php` 的真实路径 |
| PHP 源码作为文本下载 | 网站未启用 PHP 处理 | 立即停止该站公开访问，修正 PHP 配置后检查是否发生源码泄露 |
| 提示先启用 HTTPS | 浏览器是否使用 HTTPS、源站 PHP 的 HTTPS 参数 | 配好证书和 PHP HTTPS 参数，CDN 使用源站 HTTPS |
| 找不到 setup-link.txt | 是否访问过网站、storage 是否可写 | 先访问正确 HTTPS 域名，再在服务器文件管理器读取 |
| 提示配置目录不可用 / 不可写 | PHP 用户、storage 权限、open_basedir | 允许实际 PHP 用户读写项目私有目录，不使用 777 |
| 提示后台进程不支持 | `proc_open`、`proc_close` 是否被禁用 | 仅为本站运行环境允许必需函数 |
| 通信服务启动失败 / 503 | 可执行权限、架构、内存、内部端口冲突 | 查看私有启动日志，核对对应二进制 |
| 页面正常但 Agent 始终离线 | WSS 代理、证书、CDN 挑战、节点出站网络 | 检查两个精确路由和 Agent 日志 |
| 终端连接失败 | 节点在线、授权 SSH 服务、主机指纹 | 修复节点 SSH 服务；指纹变化先核对系统是否重装 |
| 登录或操作返回 429 | 当前来源请求过多或登录限额 | 等待限额恢复，排查自动重试程序；不要关闭限流 |
| 返回 421 | 域名 / 端口与安装时不同 | 使用正式安装域名，迁移时同步 origin |
| 验证器不通过 | 时间偏差、验证码刚被使用过 | 校准时钟，等待下一组验证码 |
| Telegram 测试失败 | Bot 是否已 /start、Chat ID、网络、Token | 检查后台脱敏错误；不要公开 Token 请求 URL |
| 站名改后仍显示旧值 | 是否访问同一域名、CDN 是否缓存整页/API、资源发布顺序 | 清理错误缓存规则，保留接口 `no-store`，核对版本 |
| 角标是“通讯 —” | 节点是否在线、有无新 RTT 样本 | 等待上报；离线没有延时值是正常行为 |
| 浏览器出现 502 | PHP-FPM / WSS 上游是否就绪 | 分别检查本站 PHP 和内部服务，避免重启无关应用 |

常用检查命令：

```sh
/www/server/nginx/sbin/nginx -t
ss -lntp | grep '127.0.0.1:19281'
ls -ld /www/wwwroot/probe/storage
ls -l /www/wwwroot/probe/bin/
```

私有日志位于 `storage/startup.log`、`storage/control/service.log` 等运行生成位置，以实际文件为准；同时检查本站的 Nginx 和 PHP 错误日志。不要将整个 storage 或未脱敏日志发送到公开论坛。

不要用直接访问内部健康接口的 403 判断服务一定故障：该接口需要 PHP 派生密钥，拒绝未经授权的请求属于预期行为。

## 16. 运行原理与安全边界

```text
访客 / 管理员浏览器 ── HTTPS ── Nginx ── PHP 页面、安装器和 API 网关
                                │                     │
                                │                回环鉴权接口
                                │                     │
                                └── WSS ── Rust 主控（本机 19281）
                                                  ▲
                                                  │ WSS + 独立节点密钥
                                              Rust 被控 Agent
                                                  │
                                            节点本机 SSH 服务
```

PHP 启动通信监督进程，监督进程在工作进程异常退出后恢复它。主控重启后，网页请求或 Agent 重连的 WSS 路由会触发唤起流程；因此需保留本教程的 `error_page 502` 配置，并保证 Nginx / PHP 在系统启动后正常运行。

密码使用 bcrypt；管理写请求具有会话、CSRF 和 Origin 校验；二步验证使用 TOTP；Agent 和终端通过 WSS；节点密钥、SSH 私钥和通知 Token 使用本地随机主密钥加密。详细实现与限制见 [Rust 安全说明](RUST-SECURITY.md)，依赖扫描中的 RSA 上游告警及当前可达性判断也在该文档中保留。

这些保护不代替服务器管理。能够读取整个私有目录或修改程序的系统管理员 / PHP 账户属于可信边界。多站点同机时，独立 PHP 用户与目录隔离能够减少其他网站被入侵后的影响；共同使用 `www` 账户不能提供同等的账户隔离。

测试报告描述实际检查范围及发现的问题，不代表永久不存在漏洞。保持操作系统、Nginx、PHP 和面板更新，并维护可恢复的私密备份。
