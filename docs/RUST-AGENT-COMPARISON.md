# Go / Rust Agent 快速实测

比较对象：Go 0.1.2-test 与 Rust 0.1.3-rust.1，均在同一 Debian 12 amd64 测试节点测试。两者使用同一原始 Go wire.Peer / wire.Tunnel 对端，通过回环 TLS/WSS 传输两个 TCP 回显通道；Agent 均限制为单核 CPU 10%、内存 96 MiB、32 个任务、128 个文件描述符。此测试衡量应用隧道处理开销，不代表公网带宽或完整 SSH 加密吞吐。

| 指标 | Go | Rust | 变化 |
|---|---:|---:|---:|
| 静态 amd64 二进制 | 7,028,896 B | 2,959,296 B | 减少 57.90% |
| 等量负载平均 RSS | 12.57 MiB | 2.92 MiB | 减少 76.80% |
| 等量负载 CPU（单核百分比） | 2.0073% | 1.3256% | 减少 33.96% |
| 等量负载往返 p95 | 3.730 ms | 2.519 ms | 降低 |
| CPU 10% 饱和时单向有效负载 | 3.637 MiB/s | 5.135 MiB/s | 提高 41.19% |

等量场景每组约 237 秒，包含 60 秒空闲、120 秒传输、3 次强制断线恢复及恢复后空闲。每组完成 2400 次往返、每方向 75 MiB、0 数据或协议错误。饱和场景每组 45 秒持续传输，同样 0 错误，并各自再次完成 3 次重连。第三条超额隧道均被拒绝。

Rust 版另外完成原始 Go 协议兼容测试、TLS 证书链和主机名拒绝测试、无效报文与通道边界测试，以及真实浏览器 SSH/SFTP 文件编辑测试。短时负载中 Rust 的 CPU、RSS 与吞吐更好，因此迁移测试主控。

24 小时低负载双实例观察单独运行，持续时间和阶段结果记录于发布测试报告；未跑满前不得称为“24 小时稳定性通过”。ARM64 Agent 已交叉编译为静态二进制，本次没有 ARM64 真机可供验证。
