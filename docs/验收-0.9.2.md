# 0.9.2 终端心跳隔离与异常重连验收

日期：2026-10-04。主控及前端 0.9.2，Agent 保持 0.2.1。开发、构建和故障注入均在隔离开发环境进行。

## 发现与修复

近期约 74 分钟的终端断开记录为 `input_stalled`。旧代码把 SSH 写入失败与 30 秒写入超时归为同一原因，因此不能仅凭历史记录断定该次一定是浏览器心跳丢失。

本次复现了明确的双向阻塞路径：WebSocket 接收循环在写入 SSH 输入时等待远端接收窗口，无法继续处理浏览器输出确认与 Pong；输出无法继续时，又会延迟远端接收输入。相同真实节点负载中，旧版约 44.56 秒后异常关闭且输出未完成，新版在 33.87 秒完成 8 MiB 输出和 2.125 MiB 输入，期间收到心跳并保持连接。

修复将 SSH 输入写入独立为有界、顺序任务；窗口调整也进入该队列。接收循环不等待文件错误响应或通知发送。Ping/Pong 采用独立有界队列，在写出时优先处理；物理网络阻塞仍保留超时与资源上限。输入写入错误和超时分别记录。迟到、重复或不匹配的节点延迟 Pong 不再关闭整条 Agent 链接，正常监控数据仍按既有期限检查存活。

异常断线后按 2、5、10 秒最多重新连接三次，每次申请当前管理员登录下的全新单次票据，建立新的 SSH 会话。未重复发送输入，不保存旧 shell。稳定 60 秒后恢复重试额度。主动关闭、取消重试、正常远端退出与明确授权失败停止重试。

## 安全检查与范围

匿名管理及终端访问、缺失/跨域 Origin、错误/跨登录/重放票据、旧 resume 握手、CSRF 缺失、退出撤权、私密文件隔离、安全 Cookie、主题输入校验均通过。重试不会绕过授权或恢复被撤销登录。源码密钥扫描没有发现秘密；npm 与 Agent 依赖审计无告警。

主控 Cargo Audit 仍有已记录的 RUSTSEC-2023-0071（RSA 依赖），没有新增告警；依赖锁定除项目版本号外未改变。受管身份仅接受 Ed25519 私钥，现有可达性说明见 RUST-SECURITY.md。本次不把该上游告警标记为已修复。

真实长连接观察为上述时长，并非已完成一小时或全天真实稳定性试验；50 次强制重新协商使用内存测试端点，不冒充生产一小时复现。历史每一次断线是否同因无法仅凭旧记录确认。AMD64 完成运行测试；ARM64 完成交叉编译与静态 ELF 架构检查，未做 ARM64 真机验收。扫描不能保证不存在未知漏洞。

安装方式继续使用 Nginx + PHP 8.0+；已有 Agent 无需重装，更新主控后刷新页面使用新界面。
